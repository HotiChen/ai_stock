## 🏗️ 需要重新架構的部分

### A1 — 持倉 Single Source of Truth（最緊急）
**現狀：** 三個地方記錄持倉：`portfolio.json`、`sim_positions.json`、`learning.db`  
**問題：** `handle_select_plan` 依序寫三個地方，中途崩潰無回滾  
**目標：** 選一個 master，其他廢棄或降為 derived view

### A2 — `app.py` 拆分（2027 行 God Object）
**現狀：** UI + 業務邏輯 + API 呼叫 + 資料存取全在同一個檔案  
**目標：**
```
views/          ← 純 Streamlit UI
services/       ← 業務邏輯（建倉、結算、停損）
data_access/    ← DB/JSON 讀寫
```

### A3 — `telegram_bot.py` 瘦身（1036 行）
**現狀：** I/O 層混入業務邏輯  
**目標：** telegram_bot.py 只負責收發訊息，業務邏輯移到 services/

### A4 — 統一 API Client 層
**現狀：** TWSE 呼叫散落、weekly_report_runner 繞過統一入口  
**目標：** 所有外部 API 呼叫通過帶 retry + timeout + rate-limit 的統一 client

### A5 — 專案 Package 結構
**現狀：** 63 個 .py 全在根目錄  
**目標：**
```
ai_stock/
  core/       ← learning_db, portfolio, strategy_planner
  services/   ← chip_data, morning_strategy, weekly_report
  interfaces/ ← telegram_bot, app
  tests/
```
